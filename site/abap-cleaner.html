origami and ABAP Cleaner

ABAP Cleaner cleans up code: it replaces obsolete statements, removes unused variables and also lays the code out. origami only lays it out. This page compares only the layout: the same code, formatted by ABAP Cleaner's layout rules and by origami.

ABAP Cleaner
1.29.2, default profile reduced to its 47 layout rules with their default options (how). Checked on 2026-11-23 on the 1,964 ABAP and 144 CDS files of the test corpus: these rules change no code and delete no comment; the only reordering is a closing bracket moved in front of a comment or pragma.
origami
origami 0.2.1 (style edition 2026), default settings.
Both
Line width 120, keywords in upper case, indent 2.

The same code, twice

Each input was run through both tools as it is. The differences come from two choices: origami breaks every line that is too long and ignores the author's line breaks, and it aligns columns only inside one statement.

Method calls

Both hang the parameters behind the opening bracket and align the = signs. A call with two or more parameter keywords puts each keyword on its own line in both tools. origami aligns the = signs per keyword, ABAP Cleaner across all of them.

Before
lo_service->read( exporting iv_id = lv_id importing es_data = ls_data ).
lo_service->check( exporting iv_id = lv_id ).
data(lv_result) = lo_calculator->calculate( iv_amount = lv_amount iv_currency = lv_currency iv_date = sy-datum iv_rounding = abap_true ).
ABAP Cleaner, layout rules
lo_service->read( EXPORTING iv_id   = lv_id
                  IMPORTING es_data = ls_data ).
lo_service->check( EXPORTING iv_id = lv_id ).
DATA(lv_result) = lo_calculator->calculate( iv_amount   = lv_amount
                                            iv_currency = lv_currency
                                            iv_date     = sy-datum
                                            iv_rounding = abap_true ).
origami
lo_service->read( EXPORTING iv_id = lv_id
                  IMPORTING es_data = ls_data ).
lo_service->check( EXPORTING iv_id = lv_id ).
DATA(lv_result) = lo_calculator->calculate( iv_amount   = lv_amount
                                            iv_currency = lv_currency
                                            iv_date     = sy-datum
                                            iv_rounding = abap_true ).

Lines longer than the limit

origami breaks every statement that does not fit into the line width: before AND and OR, and before each SQL clause. ABAP Cleaner's layout rules align lines that are already broken, but they leave a long line as it is.

Before
if lv_amount > 0 and lv_currency is not initial and ls_data-status = 'A' and ls_data-created_by = sy-uname and lv_flag = abap_true.
  book( ).
endif.
select carrid, connid, fldate from sflight where carrid = @lv_carrier and fldate >= @sy-datum into table @data(lt_flights).
ABAP Cleaner, layout rules
IF lv_amount > 0 AND lv_currency IS NOT INITIAL AND ls_data-status = 'A' AND ls_data-created_by = sy-uname AND lv_flag = abap_true.
  book( ).
ENDIF.
SELECT carrid, connid, fldate FROM sflight
  WHERE carrid = @lv_carrier AND fldate >= @sy-datum
  INTO TABLE @DATA(lt_flights).
origami
IF lv_amount > 0
    AND lv_currency IS NOT INITIAL
    AND ls_data-status = 'A'
    AND ls_data-created_by = sy-uname
    AND lv_flag = abap_true.
  book( ).
ENDIF.
SELECT carrid, connid, fldate
    FROM sflight
    WHERE carrid = @lv_carrier AND fldate >= @sy-datum
    INTO TABLE @DATA(lt_flights).

Your own line breaks

origami does not keep line breaks: whatever fits goes on one line, so two authors always get the same result. ABAP Cleaner keeps the author's breaks and aligns around them.

Declarations

ABAP Cleaner aligns TYPE across separate DATA statements and puts each item of a chain on its own line. origami aligns only inside a chain it has to break, and keeps a chain that fits on one line.

Before
data lv_count type i.
data lt_flights type standard table of sflight with empty key.
data lo_logger type ref to zcl_logger.
data: lv_a type i, lv_long_name type string.
types: begin of ty_item, id type i, name type string, end of ty_item.
ABAP Cleaner, layout rules
DATA lv_count   TYPE i.
DATA lt_flights TYPE STANDARD TABLE OF sflight WITH EMPTY KEY.
DATA lo_logger  TYPE REF TO zcl_logger.
DATA: lv_a         TYPE i,
      lv_long_name TYPE string.
TYPES: BEGIN OF ty_item,
         id   TYPE i,
         name TYPE string,
       END OF ty_item.
origami
DATA lv_count TYPE i.
DATA lt_flights TYPE STANDARD TABLE OF sflight WITH EMPTY KEY.
DATA lo_logger TYPE REF TO zcl_logger.
DATA: lv_a TYPE i, lv_long_name TYPE string.
TYPES: BEGIN OF ty_item,
         id   TYPE i,
         name TYPE string,
       END OF ty_item.

Method signatures

ABAP Cleaner keeps IMPORTING behind the method name and aligns the types in a table. origami gives each section keyword its own line and does not align types, so renaming one parameter changes one line.

Before
class zcl_rates definition public final create public.
  public section.
    methods calculate importing iv_amount type p iv_currency type waers iv_date type d returning value(rv_result) type p raising zcx_calc_error.
    methods reset.
endclass.
ABAP Cleaner, layout rules
CLASS zcl_rates DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    METHODS calculate IMPORTING iv_amount        TYPE p
                                iv_currency      TYPE waers
                                iv_date          TYPE d
                      RETURNING VALUE(rv_result) TYPE p
                      RAISING   zcx_calc_error.

    METHODS reset.
ENDCLASS.
origami
CLASS zcl_rates DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    METHODS calculate
        IMPORTING
          iv_amount TYPE p
          iv_currency TYPE waers
          iv_date TYPE d
        RETURNING
          VALUE(rv_result) TYPE p
        RAISING
          zcx_calc_error.
    METHODS reset.
ENDCLASS.

Comments and blank lines

origami puts exactly one space before an end-of-line comment and never changes comment text, apart from aligning ABAP Doc. ABAP Cleaner keeps aligned comments, adds a space after " and adds blank lines, for example after declarations.

CALL FUNCTION

Same structure, two details: origami indents the parameter groups by four spaces, ABAP Cleaner by two and also aligns the keywords and = signs across groups.

Before
call function 'Z_FLIGHT_TRAVEL_CREATE' exporting is_travel = ls_travel it_booking = lt_booking importing es_travel = ls_result exceptions not_found = 1 others = 2.
ABAP Cleaner, layout rules
CALL FUNCTION 'Z_FLIGHT_TRAVEL_CREATE'
  EXPORTING  is_travel  = ls_travel
             it_booking = lt_booking
  IMPORTING  es_travel  = ls_result
  EXCEPTIONS not_found  = 1
             OTHERS     = 2.
origami
CALL FUNCTION 'Z_FLIGHT_TRAVEL_CREATE'
    EXPORTING is_travel  = ls_travel
              it_booking = lt_booking
    IMPORTING es_travel = ls_result
    EXCEPTIONS not_found = 1
               OTHERS    = 2.

Letter case

Both write keywords in upper case and identifiers without a lower-case letter in lower case; an identifier in mixed case keeps it. Literals and comments are never changed. The only difference here is the blank line ABAP Cleaner adds after the declarations.

Aligned statements, COND and SELECT lists

Both tools align consecutive ALIASES, REDEFINITION and FOR TESTING declarations, assignments to the same structure, ABAP Doc parameters, the branches of COND and a SELECT list with aliases, and both remove the space before the period. The differences: origami indents the SQL clauses by four spaces and keeps a method signature that fits on one line; ABAP Cleaner indents by two, aligns the signature in a table and adds blank lines.

Before
CLASS lcl_flights DEFINITION FOR TESTING RISK LEVEL HARMLESS DURATION SHORT.
  PUBLIC SECTION.
    INTERFACES zif_reader.
    ALIASES read FOR zif_reader~read.
    ALIASES read_all_entries FOR zif_reader~read_all_entries.
    "! Reads one flight
    "! @parameter iv_carrier | Airline
    "! @parameter iv_connection_number | Flight number
    "! @raising zcx_not_found | No such flight
    METHODS get_flight IMPORTING iv_carrier TYPE s_carr_id iv_connection_number TYPE s_conn_id RAISING zcx_not_found.
    METHODS get_name REDEFINITION.
    METHODS get_description REDEFINITION.
  PRIVATE SECTION.
    METHODS reads_one_flight FOR TESTING.
    METHODS fails_without_carrier FOR TESTING RAISING cx_static_check.
ENDCLASS.

Every ABAP Cleaner rule

ABAP Cleaner 1.29.2 has 100 rules. 53 of them change code, comments or names; origami never does that, it checks its own output token by token. Of the other 47, origami does 20 the same way and covers 23 with its own layout; 4 have no counterpart.

  • Same origami does the same: 20
  • Own layout origami covers this with its own layout: 23
  • No layout rule origami does not have: 4
  • Not a goal changes code, comments or names, which origami never does: 53
