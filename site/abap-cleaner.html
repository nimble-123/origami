origami and ABAP Cleaner

ABAP Cleaner cleans up code: it replaces obsolete statements, removes unused variables and also lays the code out. origami only lays it out. This page compares only the layout: the same code, formatted by ABAP Cleaner's layout rules and by origami.

ABAP Cleaner
1.29.2, default profile reduced to its 47 layout rules with their default options (how). Checked on 2026-11-23 on the 1,964 ABAP and 144 CDS files of the test corpus: these rules change no code and delete no comment; the only reordering is a closing bracket moved in front of a comment or pragma.
origami
origami 0.4.3 (style edition 2026), default settings (style aligned).
Both
Line width 120, keywords in upper case, indent 2.

The same code, twice

Each input was run through both tools as it is. Since 0.4, origami's default style follows ABAP Cleaner's layout; the differences that remain come from one choice: origami breaks every line that is too long and ignores the author's line breaks. style = "compact" keeps the layout of origami 0.3.

Method calls

Both hang the parameters behind the opening bracket, pad the parameter keywords to the longest one and align the = signs across all of them. A call with two or more parameters puts each on its own line, and one with two or more keywords each keyword, even when the call would fit on one line.

Before
lo_service->read( exporting iv_id = lv_id importing es_data = ls_data ).
lo_service->check( exporting iv_id = lv_id ).
data(lv_result) = lo_calculator->calculate( iv_amount = lv_amount iv_currency = lv_currency iv_date = sy-datum iv_rounding = abap_true ).
ABAP Cleaner, layout rules
lo_service->read( EXPORTING iv_id   = lv_id
                  IMPORTING es_data = ls_data ).
lo_service->check( EXPORTING iv_id = lv_id ).
DATA(lv_result) = lo_calculator->calculate( iv_amount   = lv_amount
                                            iv_currency = lv_currency
                                            iv_date     = sy-datum
                                            iv_rounding = abap_true ).
origami
lo_service->read( EXPORTING iv_id   = lv_id
                  IMPORTING es_data = ls_data ).
lo_service->check( EXPORTING iv_id = lv_id ).
DATA(lv_result) = lo_calculator->calculate( iv_amount   = lv_amount
                                            iv_currency = lv_currency
                                            iv_date     = sy-datum
                                            iv_rounding = abap_true ).

Lines longer than the limit

origami breaks every statement that does not fit into the line width: before AND and OR, and before each SQL clause. ABAP Cleaner's layout rules align lines that are already broken, but they leave a long line as it is.

Before
if lv_amount > 0 and lv_currency is not initial and ls_data-status = 'A' and ls_data-created_by = sy-uname and lv_flag = abap_true.
  book( ).
endif.
select carrid, connid, fldate from sflight where carrid = @lv_carrier and fldate >= @sy-datum into table @data(lt_flights).
ABAP Cleaner, layout rules
IF lv_amount > 0 AND lv_currency IS NOT INITIAL AND ls_data-status = 'A' AND ls_data-created_by = sy-uname AND lv_flag = abap_true.
  book( ).
ENDIF.
SELECT carrid, connid, fldate FROM sflight
  WHERE carrid = @lv_carrier AND fldate >= @sy-datum
  INTO TABLE @DATA(lt_flights).

Method signatures

Both align the section keywords, names and types in a table. origami always starts the table on the line below the method name; ABAP Cleaner keeps the first keyword where the input has it, here behind the name.

Before

  public section.
    methods calculate importing iv_amount type p iv_currency type waers iv_date type d returning value(rv_result) type p raising zcx_calc_error.
    methods reset.
endclass.

CLASS zcl_rates DEFINITION PUBLIC FINAL CREATE PUBLIC.

Aligned statements, COND and SELECT lists

Both tools align consecutive ALIASES, REDEFINITION and FOR TESTING declarations, assignments to the same structure, ABAP Doc parameters, the branches of COND and a SELECT list with aliases, indent the SQL clauses by two, align the method signature in a table and add blank lines between the sections and declaration groups.

    ALIASES read_all_entries FOR zif_reader~read_all_entries.

    METHODS get_name REDEFINITION.
    METHODS get_description REDEFINITION.
  PRIVATE SECTION.
    METHODS reads_one_flight FOR TESTING.
    METHODS fails_without_carrier FOR TESTING RAISING cx_static_check.
ENDCLASS.

Constructor expressions, SORT and CATCH

Both put each component of a VALUE or NEW expression and of a table expression on its own line once there are two, each table row on its own line, the rows of a FOR below the iteration, and each sort field and exception class on its own line. ABAP Cleaner leaves REDUCE as written; origami puts INIT, FOR and NEXT below each other.

Before
ls_flight = VALUE #( carrier_id = 'LH' connection_id = '0400' flight_date = sy-datum ).
mt_items = VALUE #( ( id = 1 name = `Alpha` ) ( id = 2 name = `Beta` ) ).
mt_items = VALUE #( BASE mt_items ( id = 3 name = `Gamma` ) ).
mt_ids = VALUE #( FOR ls_item IN mt_items WHERE ( id > 1 ) ( ls_item-id ) ).
lv_total = REDUCE i( INIT sum = 0 FOR ls_item IN mt_items NEXT sum = sum + ls_item-id ).
DATA(ls_alpha) = mt_items[ id = 1 name = `Alpha` ].
lo_log = NEW zcl_log( iv_object = 'ZFLIGHT' iv_subobject = 'BOOKING' ).
SORT mt_items BY name ASCENDING id DESCENDING.
TRY.
    lo_log->save( ).
  CATCH zcx_log_full zcx_log_locked INTO DATA(lx_error).
    CLEAR: ls_flight, mt_items.
ENDTRY.
ABAP Cleaner, layout rules
ls_flight = VALUE #( carrier_id    = 'LH'
                     connection_id = '0400'
                     flight_date   = sy-datum ).
mt_items = VALUE #( ( id = 1 name = `Alpha` )
                    ( id = 2 name = `Beta` ) ).
mt_items = VALUE #( BASE mt_items
                    ( id = 3 name = `Gamma` ) ).
mt_ids = VALUE #( FOR ls_item IN mt_items WHERE ( id > 1 )
                  ( ls_item-id ) ).
lv_total = REDUCE i( INIT sum = 0 FOR ls_item IN mt_items NEXT sum = sum + ls_item-id ).
DATA(ls_alpha) = mt_items[ id   = 1

                      iv_subobject = 'BOOKING' ).

                 id DESCENDING.
TRY.
    lo_log->save( ).
  CATCH zcx_log_full
        zcx_log_locked INTO DATA(lx_error).
    CLEAR: ls_flight,
           mt_items.
ENDTRY.

Every ABAP Cleaner rule

ABAP Cleaner 1.29.2 has 100 rules. 53 of them change code, comments or names; origami never does that, it checks its own output token by token. Of the other 47, origami does 33 the same way and covers 13 with its own layout; 1 have no counterpart.

  • Same origami does the same: 33
  • Own layout origami covers this with its own layout: 13
  • No layout rule origami does not have: 1
  • Not a goal changes code, comments or names, which origami never does: 53
