One line through origami

One call, 104 characters long, and what origami does with it, step by step. Everything on the sheet is computed by origami itself, compiled to WebAssembly and running in this page.

1Read 2Fold 3Check 4Explain 5Write
72

  1. 1 Read

    origami lexes the statement into tokens. What sits inside a literal, a comment or a pragma is copied as it is, character for character; here that is the literal 'A'.

  2. 2 Fold

    It lays the statement out for the line width. At 72 the call would end at column 103, so it folds: one parameter per line, aligned. Drag the margin on the sheet, or focus it and use the arrow keys, to try another width.

    The sheet uses the style compact, which keeps a call on one line while it fits; the default style, aligned, puts each parameter on its own line at every width.

  3. 3 Check

    Before anything is written, origami lexes its own output again and compares it with the input, token by token: the same tokens in the same order, glued or spaced as before. Only whitespace, line breaks and the case of keywords may differ.

    A simulation of a formatter bug, in this page only: it removes the space in front of sy-datum in the output. If the check finds a difference, origami prints the statement again as it was written and reports W001, as on the sheet. If it still differs, the file stays unchanged (X001).

  4. 4 Explain

    Below each construct it broke, origami --review names the rule and the column the line would have ended at. Each rule is written down in STYLE.md.

  5. 5 Write

    Only then is the file written. In VS Code, origami: Preview Changes shows the same changes in the diff view first.

    How fast that is on real files

When the check fails, your code stays as it is

The check runs on every file, every time. Nothing else may differ between input and output than whitespace, line breaks and letter case.

  • A statement origami does not understand keeps its own line breaks. It is re-indented with its block and reported as W003.
  • A file with a structural error, such as a missing period or an unclosed IF, is never touched. You get the line and column instead.
  • Embedded languages (AMDP, native SQL, macros) are copied byte for byte.

Fast enough for every save

          
A median file takes 0.08 ms in a running editor or agent and 2.2 ms as a new process, start included; 99 % of files take under 5 ms. The 2,100-file test corpus takes 0.2 s, so format-on-save and pre-commit hooks stay out of your way.

Install

          
A single binary for macOS, Linux and Windows. It reads origami.toml for line width, indentation and keyword case.

        


        

          

            
Homebrew

            
For macOS and Linux.

            

              
brew install nimble-123/tap/origami

              
            

          

          

            
Cargo

            
On any platform with Rust. Release binaries for macOS, Linux and Windows, each with a .sha256 file, are on the releases page.

            

              
cargo install abap-origami

              
            

          

          

            
VS Code

            
Install the extension from the Marketplace or the .vsix in every release, then make origami the formatter. It works with ADT for VS Code and adds origami: Preview Changes.

            

              
"[abap]": { "editor.defaultFormatter": "nimble-123.abap-origami" },
"[acds]": { "editor.defaultFormatter": "nimble-123.abap-origami" },
"editor.formatOnSave": true,
"editor.formatOnSaveMode": "modifications"

              
            

          

          

            
GitHub Actions

            
Checks only the lines a pull request touches and shows findings as code-scanning annotations.

            

              
# .github/workflows/origami.yml
on: [pull_request]
permissions: { contents: read, security-events: write }
jobs:
  format:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: nimble-123/origami@v0.4.3
        with:
          args: --check --changed origin/${{ github.base_ref }}
          sarif: "true"

              
            

          

          

            
pre-commit / CI

            
A pre-commit hook that checks, or rewrites, the files you commit. GitLab CI and Azure Pipelines are in the CI guide.

            

              
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/nimble-123/origami
    rev: v0.4.3
    hooks:
      - id: origami        # check only
      # - id: origami-fix  # rewrite files

              
            

          

          

            
AI agents (MCP)

            
origami --mcp runs an MCP server with the tools format and format_files; agents get compact diagnostics with a next step.

            

              
claude mcp add origami -- origami --mcp

              
            

          

        


        

          
Then, in a repository

          
origami                  # format all ABAP and CDS files below .
origami --review         # show what would change, and why lines break
origami --check          # CI: exit 1 if anything would change
origami --changed main   # only lines changed against main (+ new files)
